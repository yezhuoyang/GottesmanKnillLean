# GottesmanKnillLean

Formalization of Gottesman Knill Lean theorem. The theorems is the Corner stone for QEC circuit, where we can use stabilizer formalism to simulate large scale Clifford circuit efficiently. This project also formally prove the size and structure of Clifford group, which is reusable for QEC community.

# Proof blue print

1. **Pauli group `P_n`.** Every element has the form `a₀ · (a_1 ⊗ … ⊗ a_n)` with `a₀ ∈ {±1, ±i}` and `a_i ∈ {I, X, Y, Z}`. Consequences: `|P_n| = 4^(n+1)`; any two elements either commute or anticommute; the largest mutually commuting subset has size `2^n`.
2. **Clifford group `C_n = N(P_n) ∩ U_n`.** Conjugation by `c ∈ C_n` sends `P_n` to itself, giving a group hom `M[c] : P_n → P_n`. Generated by `H_i`, `S_i`, `CNOT_{i,j}`.
3. **Stabilizer `Stab(ψ) := {G ∈ P_n | G ψ = ψ}`.** An Abelian subgroup of `P_n`; every element has phase `±1`.
4. **Stabilizer states.** `ψ ↦ Stab(ψ)` is injective on stabilizer states and `|Stab(ψ)| = 2^n`. In particular `Stab(|0⟩^⊗n) = ⟨Z_1, …, Z_n⟩`.
5. **Heisenberg evolution.** `Stab(U ψ) = U · Stab(ψ) · U⁻¹`. For `U ∈ C_n`, `M[U] : Stab(ψ) → Stab(Uψ)` is a group isomorphism, so it preserves both the size and any chosen `n`-generator set.
6. **Main theorem.** Starting from `|0⟩^⊗n` and applying `m` Clifford gates is equivalent to applying `m` Clifford mappings to the `n` generators `Z_1,…,Z_n`. Each generator costs `O(n)` symbols ⇒ `O(n²)` space; each Clifford gate is local ⇒ `O(n)` update ⇒ `O(mn²)` total time.



# Definitions of Pauli Group and Clifford circuit

`PauliOp n` is encoded algebraically, with no matrices:

```lean
inductive Pauli1 | I | X | Y | Z
inductive Phase  | one | negOne | i | negI

structure PauliOp (n : ℕ) where
  phase : Phase
  ops   : Fin n → Pauli1
```

Multiplication folds the per-qubit phases from `Pauli1.mul` into the global phase, giving `Group (PauliOp n)` of order `4^(n+1)`.

`QState n` and `Unitary n` are axiomatized — we postulate the group structure on `Unitary n`, its `MulAction` on `QState n`, an embedding `PauliOp.toUnitary : PauliOp n →* Unitary n`, and a distinguished `QState.zero n = |0⟩^⊗n` stabilized by every `Z_i`. The Clifford group is then:

```lean
noncomputable def Clifford (n : ℕ) : Subgroup (Unitary n) :=
  Subgroup.normalizer (pauliImage n)
```

with `H i`, `S i`, `CNOT i j` axiomatized as Clifford elements.



# Heisenberg Picture

For `c ∈ Clifford n` the conjugation action is realised as a `MonoidHom`:

```lean
noncomputable def Clifford.mapPauliHom (c : Clifford n) : PauliOp n →* PauliOp n
```

Its central property is `Stab(c • ψ) = (Stab ψ).map (mapPauliHom c)` (see [`Heisenberg.lean`](GottesmanKnill/Heisenberg.lean)). Iterating along a circuit `Gs : List (Clifford n)` produces the **tableau**:

```lean
noncomputable def tableau (Gs : List (Clifford n)) : Fin n → PauliOp n :=
  fun i => composedMap Gs (PauliOp.singleZ i)
```

— the `n` Pauli generators that classically track the stabilizer of the simulated state.



# Main Lean theorem

The main Lean theorem is stated as follows ([`MainTheorem.lean`](GottesmanKnill/MainTheorem.lean)):

```lean
theorem gottesman_knill (C : CliffordCircuit n) :
    StabSubgroup (CliffordCircuit.output C) =
      Subgroup.closure (Set.range (CliffordCircuit.tableau C))
```

i.e. the classically computed `n`-Pauli tableau really generates the stabilizer of the quantum output. Uniqueness follows:

```lean
theorem gottesman_knill_unique (C₁ C₂ : CliffordCircuit n)
    (h : Subgroup.closure (Set.range (tableau C₁)) =
         Subgroup.closure (Set.range (tableau C₂))) :
    output C₁ = output C₂
```

— so the tableau (`O(n²)` data, `O(mn²)` to update) fully determines the output state.

The `O(mn²)` time and `O(n²)` space claims are encoded explicitly in the same file via cost functions and the bound:

```lean
def tableauSpace   (n : ℕ) : ℕ := n * (n + 1)
def simulationCost (C : CliffordCircuit n) : ℕ := C.length * (n * n)

theorem gottesman_knill_complexity (C : CliffordCircuit n) :
    simulationCost C = C.length * n^2 ∧ tableauSpace n ≤ (n + 1)^2
```



# How to check the proof

## 1. Prerequisites

You need [`elan`](https://github.com/leanprover/elan) installed; the correct
Lean toolchain is pinned in `lean-toolchain` and will be downloaded automatically
the first time you invoke `lake`.

## 2. Fetching Mathlib

From the repository root, run **once** (or after any change to `lakefile.toml`):

```
lake update          # resolve and pin Mathlib in lake-manifest.json
lake exe cache get   # download a prebuilt Mathlib cache (much faster than rebuilding)
```

The second command is optional but highly recommended — without it, Lean will
recompile all of Mathlib from source, which can take an hour or more.

## 3. Building the whole library

```
lake build
```

This builds every `.lean` file under `GottesmanKnill/`. If you have outstanding
`sorry`s the build still succeeds with warnings (this is the expected state
while you are working through the TODOs).

## 4. Building a single file

When iterating on one section, point `lake build` at its module path:

```
lake build GottesmanKnill.Basic
lake build GottesmanKnill.PauliGroup
```

## 5. Listing remaining `sorry`s

To see every place where a proof is still missing, grep the source tree:

```
grep -rn "sorry" GottesmanKnill
```

Equivalently on Windows PowerShell:

```
Select-String -Path GottesmanKnill\*.lean -Pattern "sorry"
```

A more semantic check (skipping comments / strings) is to look at the
`declaration uses 'sorry'` warnings emitted by `lake build`.

## 6. Verifying that a finished theorem is axiom-clean

Once a particular theorem has been proved, you can check that it does not
secretly depend on `sorry` (or any other axiom besides the usual Lean / Mathlib
ones) by adding inside the file:

```
#print axioms GottesmanKnill.theoremName
```

and re-running `lake build` on that file. The expected output for a fully
formalized result is

```
'GottesmanKnill.theoremName' depends on axioms: [propext, Quot.sound, Classical.choice]
```

with no `sorryAx` in the list.
